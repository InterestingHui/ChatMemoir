<objective>
Make decrypt refresh incremental at the page level, so a routine GUI refresh costs seconds instead of re-AES-ing ~1GB.

Measured today: 9 changed files = ~1GB of reads+AES+writes to capture ~2.8MB (0.3%) of actually-changed pages. 6 of 9 changed files have identical size but newer mtime (in-place page rewrites — FTS indexes do this constantly), so "append-only" is provably unsafe. The fix exploits the fact that the decrypted output preserves each page's original 80B IV+HMAC tail verbatim: comparing the 64B HMAC tail per page between src ciphertext and existing decrypted file detects exactly which pages changed.

Three tasks:
1. Page-level HMAC-diff sync inside `decrypt_db_file_v4` (all callers get it free).
2. Per-file key cache in GUI passphrase refresh (removes ~15s PBKDF2 per refresh) + freshness gate 30min→10min.
3. Standalone self-check test on synthetic WCDB files.

Purpose: GUI refresh goes from minutes to seconds in steady state.
Output: Modified `memoir/decrypt/decrypt_v4.py`, `gui/decryption.py`; new `tests/test_incremental_decrypt.py`.
</objective>

Constants (already defined, reuse — do NOT redefine):
  IV_SIZE=16, HMAC_SHA512_SIZE=64, KEY_SIZE=32, AES_BLOCK_SIZE=16,
  PAGE_SIZE=4096, SALT_SIZE=16, SQLITE_HEADER=b"SQLite format 3"

WCDB v4 page layout (src encrypted file):
  reserve = 80  ((16+64 rounded up to AES block) — constant, safe to inline or hoist)
  page 0 (4096B): [salt 16B][ciphertext 4000B][IV 16B][HMAC-SHA512 64B]
  page N (4096B): [ciphertext 4016B][IV 16B][HMAC 64B]
  HMAC = HMAC(mac_key, ciphertext_region + le32(page_no_1based))
  mac_key = PBKDF2(enc_key, salt^0x3a, 2 iters, sha512)
  All-zero pages (4096 zero bytes) are stored unencrypted, copied as-is.

Decrypted output page layout (same size, page-aligned):
  page 0: [b"SQLite format 3\x00" 16B][plaintext 4000B][same 80B tail verbatim]
  page N: [plaintext 4016B][same 80B tail verbatim]
  → the 80B tail of output page i == 80B tail of src page i, always.

decrypt_db_file_v4(pkey, in_db_path, out_db_path):
  pkey = hex of the per-file enc_key (already PBKDF2-derived by caller; NOT the passphrase)

  current behavior: opens out 'wb' (full rewrite); on failure finally-removes out_db_path
